# AI Workforce OS — Secure SDLC, Dependency Security, SAST & Supply-Chain Protection Architecture

## 1. Overview & Security Architecture
AI Workforce OS enforces a deterministic **Secure Software Development Lifecycle (Secure SDLC)**. All code changes—whether generated by AI workforce agents or written by human developers—must pass defined security validation gates before release and production deployment.

```
Source Change
     ↓
Linting & Formatting Check (Pre-commit / CI)
     ↓
TypeScript Strict Mode Typecheck
     ↓
Unit & Integration Test Suite
     ↓
Secret Scanning (scripts/secret-scanner.mjs)
     ↓
Dependency Vulnerability Scan (scripts/dependency-scanner.mjs)
     ↓
SAST Security Scan (scripts/sast-scanner.mjs)
     ↓
License Audit & SBOM Generation (CycloneDX 1.5 JSON)
     ↓
Build Security Gate (BuildSecurityGateService)
     ↓
Human Approval Gate (for high-risk releases)
     ↓
Commit / Push to Protected Branch
     ↓
Production Deployment Gate
     ↓
Deploy & Post-Deployment Verification
     ↓
Audit & Zero-Trust Security Events
```

## 2. Scanner Stack & Validation Commands

| Check Type | Utility Script / Tool | CLI Command | Production Policy |
| :--- | :--- | :--- | :--- |
| **Lockfile Consistency** | `scripts/check-lockfile.mjs` | `npm run security:lockfile` | **Mandatory**. `package-lock.json` must exist and be valid v2/v3. |
| **Secret Scanning** | `scripts/secret-scanner.mjs` | `npm run security:secrets` | **Blocking**. Zero committed credentials allowed. |
| **Dependency Scan** | `scripts/dependency-scanner.mjs` | `npm run security:deps` | **Blocking**. Critical/High vulnerabilities block release. |
| **SAST Analysis** | `scripts/sast-scanner.mjs` | `npm run security:sast` | **Blocking**. Critical/High SAST findings block release. |
| **License Audit** | `scripts/license-scanner.mjs` | `npm run security:licenses` | **Blocking**. Restricted licenses (AGPL/GPL) flagged. |
| **SBOM Generation** | `scripts/generate-sbom.mjs` | `npm run security:sbom` | **Artifact**. Generates `dist/sbom.json` (CycloneDX 1.5). |
| **Pre-Commit Check** | `scripts/pre-commit-check.mjs` | `npm run security:pre-commit` | **Local Developer Experience**. Fast pre-commit verification. |
| **Build Security Gate** | `BuildSecurityGateService` | `npm run check` | **Mandatory Gate**. Fails closed for production if checks fail. |

## 3. Dependency Admission Policy & Supply-Chain Protection
AI workforce agents and human developers MUST NOT casually install arbitrary third-party npm packages.

### 3.1 Admission Rules (`PackageAdmissionPolicy`)
1. **Explicit Blacklist**: Packages with known supply-chain compromises (e.g. `event-stream`, `flatmap-stream`) are rejected automatically.
2. **Naming Patterns**: Suspicious typosquatted or malicious naming patterns are flagged.
3. **Technical Rationale Requirement**: Every package addition requires a documented technical justification (minimum 10 characters).

### 3.2 Lockfile & Script Hardening
- Dependency lockfiles (`package-lock.json`) are pinned and verified during build.
- `npm ci` is enforced in CI pipelines to prevent lockfile drift.

---

## 4. Governed Security Exception Mechanism
When an unfixable vulnerability or false-positive finding blocks a release, a governed `SecurityException` may be requested.

### 4.1 Exception Rules (`SecurityExceptionStore`)
- **Explicit & Audited**: Exceptions require a rationale, risk acceptor, environment scope, and expiration date.
- **Time-Limited**: Exceptions automatically expire after the configured time window.
- **Unbypassable Invariants**: Confirmed secret leaks (`secret_scan` criticals) and core system security invariants **CANNOT** be bypassed by an exception.

---

## 5. Build Provenance & Artifact Integrity
- **SHA-256 Digest**: Deployable build output produces an SHA-256 digest (`artifactHash`).
- **Build Provenance (`BuildProvenance`)**: Records commit SHA, repository URL, lockfile digest, environment, and list of passed security checks.
- **Deployment Gate Validation**: Production deployment requires explicit verification of security check evidence and artifact digests.

---

## 6. GitHub Actions Workflow Hardening
- Least-privilege permissions (`permissions: contents: read`).
- Matrix build testing across Node 20.x and 22.x LTS versions.
- CodeQL static analysis (`.github/workflows/codeql.yml`) on push to main and scheduled weekly runs.
- Dependabot automated weekly dependency security checks (`.github/dependabot.yml`).

---

## 7. AI Workforce Agent Execution Security Rules
1. **No Self-Certification**: AI agents cannot mark a security check as passed without actual scanner CLI or tool execution output.
2. **No Silent Suppression**: AI agents must not comment out failing assertions or add blanket ignores (`eslint-disable`, `@ts-ignore`) to pass security gates.
3. **Automated Incident Event Emission**: Security gate failures automatically emit normalized `ZTNSecurityEvent` records to the audit ledger.
