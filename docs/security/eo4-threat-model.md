# EO-4 Threat Model, Failure-Recovery Model and Release Gate (EO-4.8)

Scope: the execution chain from project request to release/rollback
(EO-2 → EO-4.7), as implemented in this repository.

**Principle: deny by default.** An operation is permitted only when all of
these checks pass, and each is re-checked at every step:

- a registered operation, allowed by a versioned policy rule;
- a qualified agent and an eligible environment;
- a live grant for the session;
- where required, an approval bound to the exact subject.

A model's output is **data**. Nothing a model produces is ever used as an
executable, an argument template, a path root, a Git remote, a deployment
target, a secret reference, a runner endpoint, a container mount or a
privilege flag.

## Failure-recovery model

| Failure                                | Resulting state                                                                                                               | Recovery                                                          |
| -------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------- |
| Agent or model failure                 | EO-4 execution never calls models; the model-provider layer has bounded, classified retries (provider tests)                  | Retry the task (bounded `maxOperatorRetries`) or request a replan |
| Tool failure                           | Receipt `tool_failure`; the session fails (single-operation) or stays open (workspace session)                                | Inspect the receipt; start a new session                          |
| Runner failure or disconnect           | `sandbox_failure` + `RUNNER_DISCONNECTED`; the session is `failed`                                                            | A new session re-routes (policy and approval re-evaluated)        |
| Instance lost mid-invocation           | Reconciled to `failed` (orphaned) or `timed_out`                                                                              | A new session                                                     |
| Workspace failure                      | Fails closed; the lease expires; state is removed only with proven ownership                                                  | Operator cleanup of the reported path; never automatic            |
| Build, test or security failure        | Domain results `BUILD_FAILED` / `TEST_FAILED` / `FINDINGS`; the verification fails and the ChangeSet is `verification_failed` | Fix the source, then verify again                                 |
| Git conflict, push rejected            | `REMOTE_CHANGED`; nothing is overwritten                                                                                      | Rebase through a new verified ChangeSet                           |
| Deployment failure, partial deployment | `failed` (with `resources` on partial)                                                                                        | Governed rollback or a new approved deploy                        |
| Health or version failure              | `degraded` / `failed`, never healthy                                                                                          | Governed rollback (automatic only if policy allows)               |
| Rollback failure                       | Release keeps its status plus `ROLLBACK_FAILED`; audited                                                                      | Retry the rollback after fixing the provider; escalate            |
| Store or audit write failure           | Protected actions abort before mutating; receipt gaps are audited; the response waits for flush (≤ 5 s)                       | Retry; see residual risk 3                                        |

## Residual risks (accepted, documented)

1. **Windows tree kill race.** A descendant that is being spawned _while_
   `taskkill /T` snapshots the tree can survive. Node has no Job Objects.
   POSIX process-group kill is not affected. Existing trees are killed
   reliably (tested).
2. **The host build runner is not isolated.** It is used only with a
   per-project `trustedHostBuild` opt-in. OS-level isolation (containers or
   VMs) is required before untrusted code is verified.
3. **Audit is write-through, not fail-closed.** Cached audit writes are
   flushed before every response, and failures are logged, but a Firestore
   outage during a flush does not roll back an action that already happened.
   High-risk mutations are gated earlier by durable reservations.
4. **No rate limiting.** Every mutation requires an authenticated, authorized
   operator, and Functions are capped at 2 instances.
5. **DNS rebinding.** Hostname checks do not resolve addresses. No
   network-enabled execution provider exists yet; one must enforce
   resolved-address checks.
6. **The Control Plane runtime is rebuilt per request.** This is slow but
   correct. Memoizing it requires read-through stores for the cached
   collections.
7. **The Money Mind local adapter** runs allowlisted `npm run
build|lint|test|typecheck` scripts of a trusted local repository. It is
   not wired into production. EO-4 build tools cannot do this.
