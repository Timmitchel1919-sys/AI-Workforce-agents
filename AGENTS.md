# Agent instructions — AI Workforce

These rules apply to every AI coding agent working in this repository
(Codex, Claude Code, and others).

## Release rule: ship after every prompt

The repository owner requires that **every completed prompt ends with a
commit, a push, and a frontend deploy**. Do not wait to be asked.

After finishing the requested work in a prompt:

1. **Validate** with the real scripts (never invent scripts):
   - UI (`ui/`): `npx tsc -b`, `npm run lint`, `npx vitest run --environment jsdom`, `npm run build`
   - Backend (repo root), only if backend files changed: `npm run check`
   - If validation fails, fix it. If it cannot be fixed, **do not ship** —
     report the failure instead.
2. **Commit** on `main` with a Conventional Commit message
   (`feat(ui): …`, `fix(auth): …`). Review `git diff` first; commit only the
   work of the prompt. Never commit secrets or `.env` values.
3. **Push** to GitHub: `git push origin main`
   (https://github.com/Timmitchel1919-sys/AI-Workforce-agents).
   - Never force-push. If the push is rejected, fetch, integrate with a normal
     merge/rebase of your own commits, re-validate, and push again.
4. **Deploy the frontend** to the existing Firebase Hosting project
   `ai-workforce-agents`:
   `firebase deploy --only hosting --project ai-workforce-agents`
   - Live URLs: https://ai-workforce-agents.web.app and
     https://ai-workforce-agents.firebaseapp.com
   - Do not create another Firebase project.
   - Deploy Functions (`--only functions`) only when backend code changed.
5. **Report** the commit SHA, push result, and deploy result (hosting URL)
   at the end of the response. If any step was skipped or failed, say so.

## Working in this repo

- **Two independent packages**: the root backend (Node ≥ 20, ESM `NodeNext` —
  `contracts/`, `core/`, `adapters/`, `control/`, `api/`, `functions/`) and the
  React 19 + Vite app in `ui/`. Each has its own `package.json`, lockfile, and
  `node_modules` — install and run commands in both where relevant.
- **Data flow**: UI → `api/` (HTTP) → `control/` (query/command) → `core/` →
  `contracts/` (ports) → `adapters/firebase/` (the only `firebase-admin`
  consumer). The UI is browser-only: it must never import Firestore,
  `firebase-admin`, `core/`, or `control/`.
- **`dist/` is deliberately committed**: Firebase Functions deploys from the
  compiled output (`.gitignore` ignores only `dist/tests/`). Backend validation
  regenerates it, so commits that touch backend code will include `dist/`
  artifacts (`build(functions): …` commits are normal).
- **`functions/index.ts` is the Functions deploy entrypoint and must stay
  thin.** The heavy runtime graph must be imported lazily in
  `loadControlPlaneHandler()` (dynamic import), not at module scope — the
  deploy analyzer aborts after ~10 s and a cold-start import of the full graph
  would fail deployment.
- **Generated files you must not hand-edit**: `functions.yaml` (regenerated by
  `npm run functions:manifest / functions:prepare`, gitignored) and
  `ui/src/dataconnect-generated/`.
- **Backend tests are fully offline** (`npm test` = build + `node --test` on
  `dist/tests`, in-memory fakes — no Firebase emulator needed). UI tests are
  Vitest + jsdom.
- **Same-origin in production**: Firebase Hosting rewrites `/api/**` to the
  `controlPlaneApi` function, so `VITE_API_BASE_URL` stays empty (same-origin);
  point it at the emulator/loopback API only for local dev.
- **Firestore/Storage rules are deny-all**; only the backend Admin SDK touches
  them. Never "fix" the rules to allow client access — the API is the only
  path by design.
- Read `docs/access-control.md`, `docs/firebase.md`, `docs/control-plane.md`
  before changing any auth, persistence, or API code.

## Guardrails that still apply

- Firebase Auth → ID token → Control Plane API → backend authorization is the
  only data path. No direct frontend Firestore access.
- **AUTHZ-1: authentication ≠ authorization.** An ID token proves only who the
  user is. Authorization comes from an **ACTIVE operator account**
  (`operators/{uid}` → status + role) re-read from Firestore on every request.
  Custom token claims are **not** authority — a role claim without an account
  grants nothing, and suspension takes effect immediately.
- The UI never sends or trusts a role; capabilities are derived server-side.
- No fabricated telemetry in the UI; label presentation content as such.
